# Analyze - `risk-session-review::file-content::default`

## Role

A human-facing presentation schema for enriching coding-agent file activity with repository metadata.

## Task

This Analyzer defines the storage and presentation contract for results produced by an external deterministic program. The program reads existing local Brain records with `gsc query`, joins them by repository-relative file path, classifies review items, and writes the results as structured JSONL and a local manifest used to create the local Brain.

The Analyzer does not require an LLM to populate its fields. When metadata is supplied directly by the deterministic program:

1. Validate every field against the schema below.
2. Preserve `read_items`, `edit_items`, and `write_items` exactly as supplied.
3. Store the validated fields as `extracted_metadata`.
4. Do not infer, expand, rewrite, or supplement missing values.

If deterministic metadata is not supplied, use empty strings and arrays. Do not attempt to recreate dependency, ownership, risk, test, or purpose metadata from the target file.

## Review Item Contract

`read_items`, `edit_items`, and `write_items` are arrays of classified review-item objects. Every item must contain exactly these presentation fields:

* `group` — a short section label such as `Change risk`, `API and dependencies`, `Tests and safeguards`, or `File context`.
* `key` — a stable machine identifier used to merge the same item across files and operations.
* `title` — a short human-facing statement such as `High-risk change` or `Public API may be affected`.
* `markdown` — the complete detail shown when a reviewer opens an occurrence.

Contract rules:

* Use standard Markdown only in `markdown`. Do not include raw HTML.
* Keep `group`, `key`, and `title` useful without reading the target file path.
* Use the same `key` only when items represent the same kind of review concern.
* `read_items` describes what a read brought into context and when that knowledge is useful.
* `edit_items` separates file context, change risk, API or dependency exposure, and test safeguards into independently reviewable items.
* `write_items` identifies a complete-file write separately from a targeted edit, then surfaces the same file context, risk, API or dependency exposure, and test safeguards. A write may create a file or replace an existing file; do not claim which occurred without separate evidence.
* Omit items whose source metadata is unavailable. Use an empty array when no items apply.
* Do not infer why an agent read or edited the file.
* Do not claim that an agent understood, remembered, or followed the file.

## Context

The metadata is a deterministic, human-ready projection of other Analyzer results. It demonstrates that GitSense Analyzers are data contracts: values may be produced by AI, static analysis, repository APIs, deterministic programs, or combinations of those sources.

## Input

Process only files supplied in the `## FILE CONTENT` message. Files supplied in `## REFERENCE FILE CONTENT` are context only and must not produce records.

## Processing Steps

1. Initialize `global_file_counter = 0`.
2. For each target file:
   a. Increment `global_file_counter`.
   b. If the target does not exist, print only: `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}} - File not found. Overview and metadata cannot be generated.`
   c. Otherwise print `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}}`, then emit the Markdown and JSON blocks below.

```markdown
# GitSense Chat Analysis
## risk-session-review::file-content::default

* **Path:** {{ANALYZER: Full File Path}}
* **Chat ID:** {{ANALYZER: Chat ID from file context}}
* **Producer:** Deterministic external program

## Read Items

{{ANALYZER: List read_items exactly as supplied, or state "No read items were supplied."}}

## Edit Items

{{ANALYZER: List edit_items exactly as supplied, or state "No edit items were supplied."}}

## Write Items

{{ANALYZER: List write_items exactly as supplied, or state "No write items were supplied."}}

## Sources

{{ANALYZER: List source_analyzers and source_fingerprint exactly as supplied.}}

### Custom Metadata Definitions

* `file_path` (string): Repository-relative target file path.
* `file_name` (string): Target filename including extension.
* `file_extension` (string): Extension without a leading dot, or an empty string when unavailable.
* `read_items` (array of objects): Classified items surfaced for a file-read event.
* `edit_items` (array of objects): Classified items surfaced for a file-edit event.
* `write_items` (array of objects): Classified items surfaced for a complete-file write event.
* `source_analyzers` (array of strings): Analyzer IDs whose metadata contributed to any review-item array.
* `source_fingerprint` (string): SHA-256 of the canonical source metadata used by the deterministic producer.

### JSON Generation and Validation Rules

The `extracted_metadata` object must be valid JSON. Do not include comments. Preserve newlines in Markdown as escaped `\n` characters. Use empty strings or arrays when values are unavailable. Objects nested inside `read_items`, `edit_items`, and `write_items` are required by this deterministic contract; do not create nested objects in any other field.
```

```json
{
  "description": "Stores deterministic change-risk review items composed from multiple GitSense Analyzer results for coding-agent read, edit, and write events.",
  "label": "Risk Session Review",
  "version": "1.0.0",
  "tags": ["deterministic", "session-review", "risk-session-review", "classified", "human-readable", "metadata-composition"],
  "requires_reference_files": false,
  "extracted_metadata": {
    "file_path": "{{ANALYZER: Repository-relative file path}}",
    "file_name": "{{ANALYZER: File name including extension}}",
    "file_extension": "{{ANALYZER: File extension without leading dot, or empty string}}",
    "read_items": {{ANALYZER: JSON array of supplied objects containing group, key, title, and markdown}},
    "edit_items": {{ANALYZER: JSON array of supplied objects containing group, key, title, and markdown}},
    "write_items": {{ANALYZER: JSON array of supplied objects containing group, key, title, and markdown}},
    "source_analyzers": {{ANALYZER: JSON array of source Analyzer IDs}},
    "source_fingerprint": "{{ANALYZER: SHA-256 supplied by the deterministic producer}}"
  }
}
```

3. Files supplied in `## REFERENCE FILE CONTENT` are context only. Do not analyze them, count them, or emit records for them.
